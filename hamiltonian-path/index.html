01 · The idea

Extend the path. Undo the last step if stuck.

A Hamiltonian path visits every vertex in a graph exactly once. There's no shortcut rule like Sudoku's row/column/box check — the only way to know a partial path is doomed is to keep extending it until it provably can't reach the remaining vertices, then backtrack.

The three moves, again

Choose an unvisited neighbor of the path's current last vertex.

Explore — recurse, assuming the path continues from there.

Un-choose — if every neighbor from here leads nowhere, remove the last vertex and let the caller try a different one.

Unlike Sudoku, there's no local constraint that instantly rules out most wrong guesses — a path can look perfectly fine for five, six, seven steps and only fail because the one remaining unvisited vertex has no edge back to where the path ended up.

Path vs. cycle

This demo looks for a Hamiltonian path (start anywhere, end anywhere, visit every vertex once) rather than a Hamiltonian cycle (which must also return to the start). The backtracking shape is identical either way.

No — determining whether a Hamiltonian path exists at all is NP-complete. Backtracking is a correct way to find one when it exists, but there's no known algorithm that's fast on every graph.
02 · The algorithm

Twelve lines, read top to bottom

This is the exact function the live demo executes — neighbors of the current last vertex are tried in ascending order, starting the path at vertex 0.

function solve(path, depth) {
  if (path.length === n) return true; // visited all
  const last = path[path.length - 1];
  for (const next of neighbors(last)) {
    if (isValid(next, path)) {
      path.push(next);              // place
      if (solve(path, depth + 1)) return true;
      path.pop();                   // undo (backtrack)
    }
  }
  return false;  // dead end, let caller backtrack
}

Base case (line 2)

Once the path's length equals the number of vertices, every vertex has been visited exactly once — the recursion unwinds with true.

The recursive step (lines 4–9)

isValid just means "not already on the path". A valid neighbor extends the path, then solve() recurses from that new last vertex. If that returns false, line 8 removes it before the loop tries the next neighbor.

What you just watched

Three ideas, all visible directly in the trace you just stepped through.

NP-complete

No shortcuts, in general

There's no known polynomial-time algorithm for this problem on arbitrary graphs — backtracking with pruning is a standard practical approach.

Real dead ends

This 7-vertex graph forces the naive ascending-neighbor search to retreat repeatedly before it finds the one path that reaches every vertex.

undo ≠ restart

Backtracking's whole trick

Every red dead end popped exactly one vertex off the path and resumed — the rest of the path built so far was left untouched.
