01 · The idea

Same three moves as any backtracking search

Choose a color for the next vertex. Explore the rest of the graph assuming that choice. Un-choose it the instant that assumption leads nowhere.

The rule that matters

Two vertices joined by an edge can never share a color. That's the entire constraint — graph coloring backtracking is just Sudoku's row/column/box rule generalized to "any two connected vertices".

Coloring vertices in a smarter order (most-constrained first) prunes dead ends earlier. This deck colors them in plain index order 0..n−1 on purpose, so the backtracking itself — not a clever heuristic — is what's on display.

k colors, not "the" answer

This demo fixes k = 3 available colors up front. With too few colors the search would fail entirely; with plenty it would never need to backtrack. Three is chosen specifically to force real dead ends.

The chromatic number is the smallest k for which a valid coloring exists at all. Finding it exactly is NP-hard in general — this demo sidesteps that by fixing k and just showing whether backtracking finds a valid coloring for that k.
02 · Why not brute force?

The obvious approach, first

Before backtracking, it's worth seeing the approach it replaces: generate every possible way to assign colors to all n vertices, then check each one. Simple, correct, and the exact reason backtracking exists.

Generate & test

Assign every vertex a color from 1 to k, in every possible combination, then check whether any edge connects two same-colored vertices. If one does, discard the whole assignment and try the next combination.

This graph has 10 vertices and k = 3 colors, so brute force would consider up to 310 = 59,049 full assignments before ever checking an edge. That's small enough to brute force here — but the same idea on a 40-vertex graph would mean checking 340 ≈ 1.2 × 1019 assignments, which is where the difference starts to matter enormously.

What backtracking changes

Instead of coloring every vertex and checking the whole graph once at the end, backtracking checks each vertex's neighbors the moment it's colored. An assignment that breaks a rule is rejected immediately — no time is spent finishing an assignment that was already doomed by its second vertex.

Not really — it's the same generate-and-test idea, just interleaved with validation instead of run afterward. That's the entire trick: it turns "check every finished assignment" into "check one vertex at a time and abandon bad ones immediately."
03 · The algorithm

Eleven lines, read top to bottom

This is the exact function the live demo executes — vertices are visited in index order, colors tried from 1 up to k.

function solve(vertex, depth) {
  if (vertex === n) return true; // all colored
  for (let c = 1; c <= k; c++) {
    if (isValid(vertex, c)) {
      color[vertex] = c;             // place
      if (solve(vertex + 1, depth + 1)) return true;
      color[vertex] = 0;             // undo (backtrack)
    }
  }
  return false;  // dead end, let caller backtrack
}

Base case (line 2)

Once every vertex index up to n has been colored, the recursion has nothing left to decide — it unwinds with true all the way up.

The recursive step (lines 3–8)

isValid checks every neighbor already colored. A valid color gets assigned, then solve() calls itself for the next vertex. If that deeper call ever returns false, line 7 erases the color before the loop tries the next one.

06 · Complexity & trade-offs

What backtracking actually buys you

n is the number of vertices (10 here) and k the number of colors (3 here). Both approaches share the same worst-case bound — the difference is how often that worst case actually gets reached.

Time & space

MetricBrute forceBacktracking
Best caseΩ(kn) — still generates every assignmentO(n·k) — every vertex resolved on its first valid color
Worst caseO(kn·E) — generate, then validate against every edgeO(kn) — same bound, pruned far earlier in practice
SpaceO(n) per candidate assignment heldO(n) recursion depth + the color array

On this graph: brute force checks up to 310 = 59,049 assignments; the live demo you ran needed 214 steps.

Advantages & disadvantages

  • Rejects a bad assignment at the first conflicting edge, not after coloring everyone
  • Simple, general-purpose — works for any graph and any k without modification
  • Complete: guaranteed to find a valid k-coloring if one exists
  • Composes naturally with better vertex/color ordering heuristics
  • Worst-case time is still exponential in the number of vertices
  • Finding the true chromatic number (smallest possible k) is NP-hard — this only answers "does k work?"
  • Naive vertex ordering can trigger far more backtracking than necessary
07 · Alternative approaches

Smarter than plain backtracking

Two very different families of techniques used in practice instead of (or alongside) exhaustive backtracking.

Greedy coloring

Visit vertices in some order and assign each the smallest-numbered color not already used by an already-colored neighbor — no recursion, no undoing, just one pass. It's fast (roughly O(V + E)) but offers no guarantee: it can use more colors than necessary, and depending on vertex order it may fail to find a valid coloring for a fixed k even when one exists.

Partially — the Welsh–Powell heuristic colors highest-degree vertices first, which tends to use noticeably fewer colors than a arbitrary order. It still isn't guaranteed optimal or even guaranteed to succeed for a fixed k, which is exactly the gap backtracking's guarantee fills.

SAT / Boolean Satisfiability

Encode the whole problem as a boolean formula: one variable per (vertex, color) pair, clauses forcing "each vertex gets exactly one color," and clauses forcing "no edge's two endpoints share a color." Hand that formula to a modern SAT solver (DPLL/CDCL-based) and let decades of solver engineering find a satisfying assignment — or prove none exists.

Modern SAT solvers include learned clauses, clever branching heuristics, and years of low-level optimization that a hand-rolled backtracking search doesn't have. For large, hard instances, reducing to SAT and calling an off-the-shelf solver often massively outperforms a naive custom search.
08 · Real-world applications

The same shape shows up outside graphs

Graph coloring is a stand-in for "assign labels from a small pool so that conflicting things never match" — a pattern with genuinely surprising reach.

Map coloring

The original motivating example: color regions on a map so no two adjacent regions share a color. The famous Four Color Theorem says four colors always suffice for any planar map — a result proved (controversially, using a computer) by Appel and Haken in 1976.

CPU register allocation

A compiler builds an "interference graph" where two variables are connected if they're both alive at the same point in a program. Assigning each variable a physical CPU register such that no two interfering variables share one is literally graph coloring, with k = the number of available registers — this is exactly how Chaitin's classic register-allocation algorithm works.

Worst case

k colors tried per vertex, n vertices deep. The neighbor check prunes this drastically in practice — this graph's trace stayed under 250 steps.

18 backtracks

Real dead ends

With only 3 colors available, this particular graph forces the naive vertex-order search to backtrack repeatedly before finding a valid coloring.

undo ≠ restart

Backtracking's whole trick

Every red dead end erased exactly one vertex's color and resumed — every other vertex's coloring so far was left untouched.
