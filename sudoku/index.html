01 · The idea

Guess. Check. Undo if wrong.

That's the entire algorithm. Backtracking explores a decision one step at a time, and the moment a decision leads nowhere, it undoes that exact decision and tries the next option — nothing more clever than that.

The three moves

Choose — pick a candidate value for the current empty cell.

Explore — recurse into the rest of the board assuming that choice.

Un-choose — if that recursive exploration fails everywhere, erase the value and let the loop try the next candidate.

Restarting from scratch would re-solve every cell that was already correct. Undoing only the most recent guess keeps everything that worked and only re-examines the one decision that didn't — that's the entire efficiency argument for backtracking over brute force.

Why Sudoku is a clean example

Each empty cell is a decision point with at most 9 candidates. The row/column/box rules give a cheap, local way to reject bad guesses immediately — so most "dead ends" are discovered fast, close to where they happened.

No — production solvers add constraint propagation and pick the most-constrained cell first. This deck uses the plain, naive version on purpose: fewer tricks means the recursion itself stays easy to see.
02 · Why not brute force?

The obvious approach, first

Before backtracking, it's worth seeing the approach it replaces: generate every possible way to fill the blanks, then check each one. It's simple to write and impossible to argue with — it's also the reason backtracking exists.

Generate & test

Fill every empty cell with some digit 1–9, in every possible combination, then check whether the finished board obeys the row/column/box rules. If it doesn't, throw the whole grid away and try the next combination.

This puzzle has 20 blank cells, so brute force would consider up to 920 ≈ 1.2 × 1019 candidate grids before the row/column/box rule ever gets consulted. The live demo you'll run later solves the same puzzle in about 320 steps.

What backtracking changes

Instead of filling in the entire board and checking it once at the end, backtracking checks the row/column/box rule after every single digit it places. The moment a digit conflicts with what's already on the board, it's rejected immediately — no time is ever spent completing a grid that was already doomed by its third cell.

Not really — it's the same generate-and-test idea, just interleaved with validation instead of run afterward. That interleaving is the entire trick: it turns "check 1019 finished grids" into "check one digit at a time and walk away from bad ones immediately."
03 · The algorithm

Thirteen lines, read top to bottom

This is the exact function the live demo executes later — not pseudocode standing in for it. Click through each block to see what it's responsible for.

function solve(board, depth) {
  const cell = findEmptyCell(board);
  if (cell === null) return true; // solved!
  const [row, col] = cell;
  for (let num = 1; num <= 9; num++) {
    if (isValid(board, row, col, num)) {
      board[row][col] = num;              // place
      if (solve(board, depth + 1)) return true;
      board[row][col] = 0;                // undo (backtrack)
    }
  }
  return false;  // dead end, let caller backtrack
}

Base case (lines 2–4)

Scan for an empty cell. If there isn't one, every cell is filled validly and the recursion can unwind with true all the way to the top.

The recursive step (lines 5–11)

Try each candidate 1–9. A valid one gets placed, then the function calls itself on the same board with one more cell filled in. If that deeper call ever returns false, line 9 erases the guess before the loop moves on.

06 · Complexity & trade-offs

What backtracking actually buys you

m is the number of empty cells (20 in this puzzle). Both approaches share the same worst-case bound — the difference is how often that worst case actually gets reached in practice.

Time & space

MetricBrute forceBacktracking
Best caseΩ(9m) — still generates every gridO(m) — every cell forced, zero backtracks
Worst caseO(9m·m) — generate, then validate eachO(9m) — same bound, pruned far earlier in practice
SpaceO(m) per candidate grid heldO(m) recursion depth + the 9×9 board

On this puzzle: brute force's theoretical ceiling is ~1019 grids; the live demo you ran needed 320 steps.

Advantages & disadvantages

  • Prunes invalid branches immediately, instead of after filling the whole board
  • Simple to implement correctly — no complex data structures required
  • Complete: guaranteed to find a solution if one exists
  • Easy to extend with heuristics (ordering, constraint propagation)
  • Worst-case time is still exponential — some puzzles resist pruning
  • Naive cell ordering can leave a lot of avoidable backtracking on the table
  • Recursion depth is bounded by empty-cell count, but very large grids stress the call stack
07 · Alternative approaches

Smarter than plain backtracking

Two families of techniques that real Sudoku solvers use instead of (or alongside) the naive row-major search this deck demonstrates.

Minimum Remaining Values (MRV)

Instead of always picking the next empty cell in reading order, pick whichever empty cell currently has the fewest legal candidates. A cell with only one option gets resolved immediately; a cell with many options is deferred until other placements narrow it down — which shrinks the branching factor exactly where it matters most.

Backtracking's cost is dominated by how wide each branch is. Choosing the most-constrained cell first means most branches are narrow (often width 1), so the search tree stays shallow and thin instead of wide and bushy.

Human-style rule solver

Real players (and many fast solvers) skip guessing entirely for easy and medium puzzles, using pure logical deduction:

Naked Singlea cell has exactly one candidate left — fill it.
Hidden Singlea candidate fits only one cell in a unit, even if that cell has others too.
Naked Pairtwo cells in a unit share the same two candidates — erase those two elsewhere in the unit.
Hidden Pairtwo candidates are confined to the same two cells — erase every other candidate from those cells.
Naked Triplethree cells jointly contain only three candidates — erase those elsewhere in the unit.
Hidden Triplethree candidates are confined to the same three cells — erase every other candidate there.

Only when these rules stall does a rule-based solver fall back to guessing — at which point it's doing backtracking again.

08 · Real-world applications

The same shape shows up outside puzzles

Sudoku is a constraint-satisfaction problem wearing a game's clothing — the underlying pattern (fill in unknowns without violating conflict rules) recurs well beyond the grid.

Resource allocation

Assigning a limited pool of interchangeable resources — exam rooms, radio frequencies, delivery time slots — to requests that must not conflict with each other is the same constraint-satisfaction shape as Sudoku's row/column/box rule, just with different "units" defining what may not collide.

Puzzle & game applications

Beyond Sudoku itself: KenKen, Kakuro, and crossword construction all reduce to constraint satisfaction over a grid. Game studios also use backtracking-style solvers to auto-generate and validate procedural puzzle content — confirming a randomly generated puzzle actually has a unique, solvable answer before showing it to a player.
